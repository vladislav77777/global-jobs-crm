# Schedule template

Create or update a schedule only when the owner requests it. Use the host's scheduling tool and the owner's timezone and selected cadence. Keep one schedule per workspace; never copy another owner's IDs, prompt, accounts or personal search criteria.

Suggested instruction:

> Read docs/INSTALL.md and agent/RUNBOOK.md in this checkout. Use this owner's private config and current Notion profile/CV. Acquire and renew the collection lease; read complete source/channel registries. Collect only enabled sources. Telegram posts should preferably be at most 14 days old and never more than 21 days; require the post date. Website listings can be older if the actual employer opening is currently verified live; use employer_open_verified=true only with that evidence. Resolve aggregator links to direct employer/contact routes. Use crm.collector with complete fresh jobs/source snapshots, apply its plan through Notion MCP and verify replay creates=0. Preserve manual statuses and correspondence. If Referral Connections is enabled, discover only existing first-degree LinkedIn connections whose verified current_company matches the selected job's company, prepare short CV-backed drafts with crm.referrals and verify duplicate-free replay. Never send referral requests or connection invitations. Read Gmail only when its connection/reading switch is On and the account matches private config. Use bounded hiring-mail queries, durable message IDs and exact application matching; update Latest reply with the latest evidenced message of any type. Unmatched mail stays in history without modifying a job. Apply an organizational mailbox label only if this owner explicitly selected that behavior. Answer bank belongs under My profile & CV. Jobs uses editable Status and a Preparation resources URL to each job’s own preparation child page. Reuse that page and its manual text; inspect children and reread after uncertain creation before creating any new resource. Supply the verified URL as draft.notion_preparation_url and synchronize it to the job. Keep one main Jobs view and no extra tracker databases. Keep all sending and live_sending Off. Release the lease in finally. Store detailed cursors privately and advance successful checkpoints only after complete coverage and verified writes. Notify only for new useful results, changed failures or required owner action.

Resolve all collection/page/view IDs from private config and live Notion discovery. The schedule runs only while its host executor is available. Moving it to a cloud executor requires independent account access, private secrets and a single shared durable ledger; this repository does not deploy that infrastructure.
